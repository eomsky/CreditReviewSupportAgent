# 병렬 심사 실행

Codespaces에서 기업 식별(F01)을 먼저 확인하고 독립적인 요인을 최대 두 개씩 처리한다. F24(상환능력)는 F13~F23의 종료 후, F30은 나머지 요인 종료 후 실행한다. 종료는 검증된 판단의 존재를 보장하지 않으며, 부족과 충돌은 종합 입력에 유지된다.

각 작업은 별도 상태 사본을 사용한다. 메인 실행만 state.json과 실행 상태를 저장한다. run lease는 동일 보고서의 중복 실행을 차단하며 모든 worker를 종료한 뒤 해제된다. 서버 장애 발생 시 신규 작업을 중단하고 진행 중인 작업의 결과를 합친다. 프로세스 강제 종료로 .run.lock이 남으면 해당 실행 프로세스가 종료됐는지 확인한 뒤 관리자가 잠금을 해제해야 한다.

공통 자료는 같은 실행/source_revision 내 dataset ID를 지정한 reuse 액션으로 가져온다. 데이터 형태, 단위, 출처 ID를 다시 검사한다. 연결/별도·대상 회사·기간의 의미상 적합성은 모델 검토 대상이며 자동 검증 완료로 간주하지 않는다. 검색/원문 읽기/계산은 실행 동안 정확히 같은 입력에만 캐시를 적용한다. PDF 추출은 내용 해시+공표일+추출기 버전으로 디스크에 보관한다.

검증된 요인 판단은 즉시 보고서 본문에 표시한다. 요인마다 문장 편집 모델을 별도로 호출하지 않는다. 마지막 종합의견은 검증된 JSON 종합 후 실제 SSE 스트림으로 출력한다. 개별 요인의 JSON 생성이 토큰 단위 본문 스트림인 것은 아니다.

performance.json에는 이번 실행의 경과 시간, 첫 새 판단 표시 시간, LLM 호출 수, 캐시 적중 및 작업별 소요 시간을 저장한다. 동시 요청 수 2는 서버 처리량과 응답시간 개선을 보장하지 않는다. 실제 문서의 총 소요시간과 결과 품질을 비교해야 한다.

Colab은 기존 Gemma4 서버를 유지한다. max_num_seqs=2 설정을 사용하며 모델/운영 HTML/기존 Drive 자산은 수정하지 않는다.
